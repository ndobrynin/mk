# Архитектура Кидаграда

Сетевая игра на React + NestJS. Сервер — единственный источник истины для партии. Один фронтовый бандл работает как сайт, VK Mini App и Яндекс Игры.

Правила карт: [rules.md](./rules.md). Локальные порты и Docker: [local-dev.md](./local-dev.md).

## 1. Решения первой версии

| Тема | Решение |
| --- | --- |
| Название | Кидаград |
| Игроки | 2–4, люди и боты |
| Режим | Только сеть, без hotseat |
| Карты | Весь каталог макета |
| Язык | `ru`, строки в одном словаре |
| Монетизация | Нет |
| Рендер стола | React + CSS, не полный PixiJS |
| Кубик | Только сервер |

## 2. Монорепозиторий

```
apps/web              Vite, React, React Router
apps/api              NestJS, Socket.IO, Passport
packages/engine       Чистый TS: состояние, команды, бот
packages/shared       Zod-схемы протокола, id карт, DTO
packages/platform     Адаптеры web / vk / yandex
```

Пакетный менеджер: pnpm. Сборка: Turborepo или Nx — на выбор при скелете, без жёсткой привязки.

`packages/engine` не импортирует Nest, React и SDK платформ. Его можно гонять в юнит-тестах без сети.

## 3. Поток данных

```
VK Mini App / Яндекс Игры / сайт
        │
        ▼
packages/platform     (логин, storage, пауза, шаринг)
        │
        ▼
apps/web              REST (аккаунт, комнаты) + Socket.IO (партия)
        │
        ▼
apps/api
   ├── Auth, Users, Identities
   ├── Rooms
   ├── GameGateway ──► packages/engine
   ├── BotScheduler
   └── Replay / history
        │
        ├── PostgreSQL
        └── Redis
```

Клиент не считает доход и не генерирует кубик. Он шлёт **команду**, получает **события** (для анимации) и при входе/реконнекте — полный **снимок** состояния.

## 4. Игровой движок

Модель:

```ts
apply(state, command, rng): { state, events } | { error }
```

- `state` — иммутабельный снимок комнаты в партии.
- `command` — дискриминированное объединение (см. §6).
- `rng` — инжект генератора. В проде — CSPRNG сервера. В тестах — seed.
- `events` — упорядоченный список фактов для клиента (`coinsTransferred`, `diceRolled`, `cardRepaired`, …).

Движок не знает сокетов. Не знает, человек это или бот: бот тоже вызывает `apply`.

### 4.1. Фазы состояния

`phase` активного хода:

1. `chooseDiceCount` — если есть Вокзал и/или Аквапарк
2. `rolling` — сервер бросает
3. `chooseTwoOfThree` — бросили 3
4. `decideReroll` — Парк развлечений
5. `decideHarbor` — Порт и сумма ≥ 10
6. `income` — авто, либо пауза на цель (`pickTvTarget`, `pickBusinessTrade`, …)
7. `cityHall` — если 0 монет
8. `build` — купить / достроить / пас
9. `endOfTurn` — венчурный фонд, проверка доп. хода, победа

Победа проверяется сразу после успешного `buildLandmark`, если набор достопримечательностей полный.

### 4.2. Каталог карт

Каждая карта — данные, не `switch` на 40 веток в гейтвее:

- `id`, `nameRu`, `color`, `activation: number[]`
- `icons[]` (wheat, cow, cup, shop, boat, mountain, office)
- `cost`, `unique`, `isLandmark`
- эффект как маленький декларативный объект (`gainFromBank`, `takeFromActive`, `perIcon`, `needsHarbor`, …)

Тексты и стоимости сверяются с Figma и с [rules.md](./rules.md). Юнит-тест на каждую карту: минимальный стол, фиксированный бросок, ожидаемые монеты.

## 5. Клиент (`apps/web`)

### Экраны первой версии

- Вход / регистрация (сайт)
- Список и создание комнат
- Лобби комнаты (слоты, боты, код, готовность)
- Стол на 4 (актуальные фреймы Figma, не «локальная игра»)
- Магазин-оверлей
- Результат партии

Устаревшие экраны hotseat не верстаем.

### Стол

React-компоненты: своё поле снизу, соперники по краям, рынок в центре. Карточка — один компонент из каталога (арт, кубик, эффект, цена).

Анимации: Framer Motion или GSAP (монеты, переворот, подсветка сработавших карт). PixiJS допустим только как слой кубика, не как весь стол.

Для VK/Яндекса — **отдельный портретный layout**: свой город крупно, соперники сжато, рынок нижней шторкой. Макет сейчас 1920×1080 landscape.

Строки UI: словарь `ru`, ключи стабильные (`card.wheatField.name`), без захардкоженного текста в JSX.

Состояние партии на клиенте: снимок + применение тех же `events` для interpolations. При рассинхроне — запросить snapshot заново.

## 6. Протокол

Транспорт партии: **Socket.IO** (reconnect и fallback в iframe надёжнее голого WebSocket). REST — аккаунт, список комнат, история.

Авторизация сокета: JWT (сайт) или one-shot ticket после проверки VK/Yandex.

### Команды клиента → сервер

| Команда | Когда |
| --- | --- |
| `room.create` / `join` / `leave` / `setReady` / `addBot` / `start` | Лобби |
| `chooseDiceCount` | 1 \| 2 \| 3 |
| `roll` | Бросок (без значения кубика) |
| `keepTwo` | Индексы двух из трёх |
| `reroll` / `keepRoll` | Парк развлечений |
| `harborAdd` / `harborSkip` | Порт |
| `pickPlayer` / `pickCard` / `pickEstablishmentType` | Цели фиолетовых и зелёных |
| `buildEstablishment` / `buildLandmark` / `passBuild` | Строительство |
| `ventureFundDeposit` / `skip` | Конец хода |

Сервер отвечает ошибкой Zod/движка, состояние не меняется.

### Сервер → клиент

- `room.state` — лобби
- `game.snapshot` — полный JSON партии
- `game.events` — пачка событий после команды (для анимации)
- `game.over` — победитель, статистика
- `presence` — онлайн, таймер хода

Версия схемы протокола в `packages/shared`. Несовместимое изменение — bump `protocolVersion`, старый клиент не заходит в новую комнату.

## 7. Сервер (`apps/api`)

Модули Nest: `Auth`, `Users`, `Rooms`, `Game`, `Bots`, `Platform`.

- Комната живёт в Redis на время партии (быстрый snapshot) и пишется в Postgres: метаданные, журнал команд, финальный replay.
- Локально Postgres и Redis — **свои** контейнеры `kidagrad-postgres` / `kidagrad-redis` на хост-портах **5435** и **6380**. Чужие инстансы на `5432`–`5434` и `6379` не использовать, см. [local-dev.md](./local-dev.md).
- API слушает **4010**, Vite — **5173**. Не `3000`.
- Горизонталь: Socket.IO Redis adapter. Партия закреплена за одним воркером через `roomId` lock в Redis, либо все команды идут через очередь с одним consumer на комнату.
- Rate limit на команды. Таймер хода: по истечении — автопасс легального минимального действия (бросить 1 кубик / не строить) либо замена на бота, если хост так настроил.

Секреты только в env. Подпись launch params VK проверяется на сервере, клиенту нельзя доверять `vk_user_id`.

## 8. Авторизация

Таблица `users` + `identities(provider, provider_id)`: `email`, `vk`, `yandex`. Один человек может привязать несколько провайдеров.

| Оболочка | Вход |
| --- | --- |
| Сайт | Почта (пароль или magic link), OAuth VK, OAuth Яндекс |
| VK Mini App | Тихий вход: проверка `sign` launch params, upsert по `vk_user_id`. Форма почты не первый экран |
| Яндекс Игры | `YaGames.getPlayer()` → наш user. API на вашем HTTPS в белом списке |

Сессии: access JWT короткий + refresh. Для мини-приложений refresh в `platform.storage`, не обязательны cookie.

## 9. Комнаты и боты

Хост создаёт комнату: слоты 2–4, публичная или по коду, опция «заполнять ботами». Старт при ≥ 2 участниках (человек + бот тоже).

Бот:

- живёт только на сервере, отдельного клиента нет;
- после `game.events`, если `activeSeat` — бот, планировщик через 0.8–1.5 с вызывает политику;
- политика v1 — эвристика: легальные команды, оценка EV дохода, приоритет достопримечательности если хватает денег и город уже «кормит»;
- политика сидит в `packages/engine`, без HTTP.

Реконнект человека: тот же `userId` садится в свой seat, получает snapshot.

## 10. Платформенный слой

`packages/platform` даёт единый интерфейс:

- `getLaunchContext()` — `web` \| `vk` \| `yandex`
- `login()`
- `storage` (локальный / Bridge / Yandex player data)
- `onPause` / `onResume` (обязательно для Яндекс Игр)
- `shareRoom(code)` — где SDK это умеет

Сборка web одна. Обёртка определяется при старте: query/hash VK, наличие `YaGames`, иначе standalone.

Ограничения iframe: никакого Pixi на весь экран как единственный рендер; осторожно с autoplay звука; CSP и `frame-ancestors` на API.

## 11. Данные

**Postgres** (локально `127.0.0.1:5435`, БД `kidagrad`)

- `users`, `identities`, `refresh_tokens`
- `rooms`, `room_seats`
- `matches` (итог, длительность, победитель)
- `match_commands` (append-only: кто, команда, время) — для replay и споров

**Redis** (локально `127.0.0.1:6380`)

- snapshot текущих партий
- presence и таймеры
- pub/sub Socket.IO
- rate limit

Контейнеры и тома только с префиксом `kidagrad`. Не подключаться к `admin-service-db`, `store-medusa-db`, `blog-translate-check-db`, `store-redis`.

Персональные данные: почта и id соцсетей. Не хранить access-токены VK/Яндекса дольше обмена на нашего пользователя. Политика конфиденциальности понадобится к модерации сторов — не в этой итерации продукта, но схема БД не должна писать лишнее.

## 12. Клиентский стек — почему не PixiJS целиком

Стол — карты, текст правил, оверлеи, форма магазина. В WebView VK и Яндекса у полного canvas типичны потеря WebGL-контекста и проблемы с текстом. React совпадает с макетом и проще для портретной вёрстки.

## 13. Этапы работ

0. Монорепо, Docker Postgres/Redis по [local-dev.md](./local-dev.md) (порты 5435 / 6380), CI, пустые `apps/web` и `apps/api`. Тикеты и флоу: [backlog](./backlog/README.md). Следующая: `python3 scripts/backlog-next.py`.
1. Auth: почта, VK, Яндекс, identities.
2. Engine: каталог, FSM, тесты каждой карты из правил.
3. Комнаты и Socket.IO, reconnection.
4. Стол и магазин по актуальным экранам Figma (desktop).
5. Боты в лобби и на таймере.
6. Адаптеры VK / Яндекс, портретный layout.
7. Таймеры, шаринг кода, история партий.

Монетизация и локальный hotseat — следующие итерации, в эти этапы не входят.

## 14. Тесты

- Engine: золотые фикстуры на порядок красных, нехватку монет, дубль + Телебашня, 3 кубика, Порт +2, снос, ремонт, парк, траулер.
- API: контракт сокета (нелегальная команда не меняет state).
- Клиент: критичные экраны без сети (лобби-мок) по желанию.

Без тестов карт движок не считается готовым к сетевой игре: расхождение «на глаз» в мультиплеере не отловить.
